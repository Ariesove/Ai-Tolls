# 🎓 AI 全栈开发实战指南 (AI Full-Stack Development Guide)

欢迎！这份 Skill 文档不仅仅是一个 RAG (检索增强生成) 系统的设计规范，它更是一份**手把手的前端 AI 开发教程**。

我们的目标是：**在实践中理解 AI，用 AI 构建 AI。**

---

## � 为什么你需要这份指南？

作为前端开发者，你可能对 AI 感到焦虑：

- _"LangChain 概念太多了，怎么学？"_
- _"RAG 到底是怎么把文档塞给 AI 的？"_
- _"我的应用怎么总是报错？"_

别担心。本指南采用 **"最小闭环 (Minimum Closed Loop)"** 原则，把宏大的概念拆解为一个个你可以立即动手写代码、立即看到效果的小任务。

---

## 🗺️ 你的学习与实战路线图 (The Roadmap)

我们将分 5 个阶段完成一个**生产级 RAG 应用**。每个阶段都是一个独立的闭环。

### 🌱 阶段一：Hello AI (理解接口与Mock)

**目标**: 跑通 UI，理解什么是 "Embedding" 和 "Vector Store"，但先用假数据。

- **概念**:
  - **Interface (契约)**: 定义 AI 组件的标准外观。
  - **Mock (模拟)**: 在没有 API Key 的情况下也能开发。
- **实战任务**:
  1.  定义 `IEmbeddingClient` (向量化接口) 和 `IVectorStore` (存储接口)。
  2.  编写 `MockEmbeddingClient`，让它返回 `[0.1, 0.2, ...]` 这样的假向量。
  3.  在控制台打印："假装正在把文本变成数字..."

### 🌿 阶段二：接入大脑 (真实 API 与 内存存储)

**目标**: 接入 OpenAI，实现真正的语义搜索。

- **概念**:
  - **Embedding**: 把 "苹果" 和 "水果" 变成在数学上距离很近的两个向量。
  - **Cosine Similarity**: 计算两个向量有多像的数学公式。
- **实战任务**:
  1.  实现 `OpenAIEmbeddingClient`，调用 API 拿到真实向量。
  2.  实现 `InMemoryVectorStore`，用一个简单的数组 `[]` 存数据。
  3.  写一个函数 `similaritySearch(query)`，找出数组里最相似的那句话。
  4.  **体验**: 上传 "公司Wi-Fi密码是123"，提问 "Wi-Fi多少"，AI 能回答了！

### 🌳 阶段三：健壮性工程 (防御性编程)

**目标**: 让应用不再脆弱，学会处理错误。

- **概念**:
  - **Result Pattern**: 不要乱抛异常，要返回 `Ok/Err`。
  - **Graceful Degradation (优雅降级)**: 向量服务挂了，聊天还能用吗？
- **实战任务**:
  1.  引入 `Result<T, E>` 类型，重构代码。
  2.  给 API 调用加上 `try/catch` 和 **自动重试 (Retry)**。
  3.  **挑战**: 断开网络，你的应用是白屏崩溃，还是弹出友好的 "网络连接中..."？

### 🌲 阶段四：记忆持久化 (IndexedDB)

**目标**: 刷新页面，知识不丢失。

- **概念**:
  - **Local-First**: 数据优先存在用户浏览器里，保护隐私，速度极快。
- **实战任务**:
  1.  安装 `idb` 库，操作浏览器的 IndexedDB。
  2.  实现 `IndexedDBVectorStore`，把之前的数组存进数据库。
  3.  **验收**: 刷新页面，之前的对话记录还在吗？

### 🌳 阶段五：用户体验极致优化 (Streaming & Workers)

**目标**: 像 ChatGPT 一样丝滑。

- **概念**:
  - **Streaming (流式传输)**: 一个字一个字地蹦出来。
  - **Web Workers**: 别让计算卡住界面。
- **实战任务**:
  1.  改造 LLM 调用为流式响应。
  2.  把繁重的向量计算扔给 Worker 线程。

## 🛠️ 架构设计原则 (写给未来的架构师)

在写代码之前，请默念这三条心法：

1.  **单一职责 (Single Responsibility)**:
    - `EmbeddingClient` 只管把字变向量，别管存哪。
    - `VectorStore` 只管存取，别管向量怎么来的。
    - `RAGService` 是指挥官，负责协调它们。

2.  **依赖倒置 (Dependency Inversion)**:
    - 业务逻辑依赖于 `Interface` (接口)，而不是具体的 `Class`。
    - _好处_: 想把 OpenAI 换成 DeepSeek？改一行代码注入新 Class 就行，业务逻辑不用动。

3.  **用户至上 (UX First)**:
    - 永远不要让用户看着空白屏幕发呆。Loading 状态、错误提示、流式反馈，缺一不可。

## 🚀 核心能力规范 (API Specs)

### 1. 知识摄入 (Ingest)

- **输入**: 文本内容 (`string`)
- **处理**:
  1.  检查非空。
  2.  切成小块 (Chunking)。
  3.  变成向量 (Embedding)。
  4.  存起来 (Store)。
- **输出**: `Result<void>` (成功或失败)

### 2. 检索 (Retrieve)

- **输入**: 用户问题 (`string`)
- **处理**:
  1.  问题变向量。
  2.  去库里找最像的 Top 4。
  3.  过滤掉不像的 (Score < 0.7)。
- **输出**: `Result<Document[]>`

### 3. 对话 (Chat)

- **输入**: 问题 + 历史记录
- **处理**:
  1.  (可选) 结合历史记录重写问题。
  2.  检索相关知识。
  3.  拼装 Prompt："你是一个助手，请根据以下知识：[检索结果] 回答用户：[问题]"
  4.  流式返回。
